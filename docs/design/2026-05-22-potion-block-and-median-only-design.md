# PD2 Filter Decorator - Potion Block + Median-Only Pricing

**Date:** 2026-05-22
**Status:** Approved, ready for implementation planning
**Amends:** `2026-05-22-pd2trader-pricing-rework-design.md`

Two independent changes to the `pd2_lootfilter` tool.

---

## Change 1: Potion display block

Force healing, mana, and rejuvenation potions to show at **every** filter level
as minimal symbols, overriding the Hiim filter's potion-hiding rules.

### Behaviour

| Item | Codes | Tag |
|------|-------|-----|
| Healing potions | `hp1`–`hp5` | red `+` |
| Mana potions | `mp1`–`mp5` | blue `+` |
| Small rejuvenation | `rvs` | purple `*` |
| Full rejuvenation | `rvl` | purple `**` |

### The block

A **static** block of four rules (identical every run - no data, no fetching):

```
// === PD2 POTION DISPLAY (generated by pd2_lootfilter) START ===
ItemDisplay[hp1 OR hp2 OR hp3 OR hp4 OR hp5]: %RED%+
ItemDisplay[mp1 OR mp2 OR mp3 OR mp4 OR mp5]: %BLUE%+
ItemDisplay[rvs]: %PURPLE%*
ItemDisplay[rvl]: %PURPLE%**
// === PD2 POTION DISPLAY (generated by pd2_lootfilter) END ===
```

- **No `FILTLVL` condition** - the rules apply at every filter level (0–11).
- **No `%CONTINUE%`** - each rule is the final display, so the Hiim filter's
  later potion-hide rules (`ItemDisplay[(hp1..hp4) FILTLVL>2]:` etc., and the
  `FILTLVL>10` catch-all) are never reached for potions.
- Injected at the same point as the price block - right after the
  `ItemDisplayFilterName[]` declarations, which is above every Hiim hide rule.

### Two blocks, both idempotent

The decorator now injects **two** delimited blocks: the existing `PD2 PRICE TAGS`
block and the new `PD2 POTION DISPLAY` block. Both are stripped and re-injected
on every run. The new marker is distinct, so existing decorated files (which
only carry the price block) upgrade cleanly - the price block strips by its own
marker, the potion block is simply added.

## Change 2: Remove the corruption ceiling

Drop top-corruption pricing entirely. Tags show only the **median**.

### Behaviour

- A normal tag is just the median: `Griswold's Valor | 0.1 HR`.
- A base shared by 2+ items (rare now that rings/amulets/jewels are excluded -
  e.g. Sacred Armor = Templar's Might + Tyrael's Might) still shows a **range**,
  but it is now `min median – max median` across those items, not
  median-to-corruption.
- The `?` low-confidence mark stays - still driven by median sample count.
- One fewer pd2trader request per uniques/sets item - roughly halves run time.

### Removed

- `PriceData.topCorruption` - `PriceData` becomes `{ median, medianSamples }`.
- `pd2trader.ts`: `parseTopCorruption`, `fetchTopCorruption`, the
  `corruption-prices` endpoint constant, the corruption response interfaces, and
  `MIN_CORRUPTION_SAMPLES`. `parseAverage` / `fetchAverage` / `Mode` stay.
- `priceCache.ts`: `topCorruption` drops from the `CacheEntry` price variant.
  Existing on-disk cache files load fine - the stale `topCorruption` field is
  simply ignored, no migration needed.
- `index.ts`: the `withCorruption` flag and the second fetch in `gatherPrices`.

## Module-by-module changes

| File | Change |
|------|--------|
| `src/types.ts` | `PriceData` loses `topCorruption` |
| `src/pd2trader.ts` | delete all corruption code; keep average + `Mode` |
| `src/priceCache.ts` | `CacheEntry` price variant loses `topCorruption`; `entryPrice` returns `{ median, medianSamples }` |
| `src/format.ts` | `formatTag` high end = `max(median)` instead of `max(topCorruption ?? median)` |
| `src/decorate.ts` | rename `BLOCK_START/END` → `PRICE_BLOCK_START/END`; add `POTION_BLOCK_START/END` + the static `POTION_BLOCK`; `stripBlock` takes start/end markers as parameters; `decorate` strips both blocks and injects both |
| `src/index.ts` | `gatherPrices` drops the corruption fetch and the `withCorruption` flag; price requests become plain names |
| `src/runes`/`pd2traderItems` | unchanged |

`buildBlock`, `resolvePricedItems`, `findInsertionLine` keep their logic;
`buildBlock` still produces the price block, `formatTag` still handles
multi-item groups.

## Testing

- `format.test.ts` - `formatTag` tests drop the corruption cases; the test
  helper's `PriceData` drops `topCorruption`. Cover single median and a
  shared-base median range.
- `pd2trader.test.ts` - drop the three `parseTopCorruption` tests; keep
  `parseAverage`.
- `priceCache.test.ts` - `CacheEntry` fixtures drop `topCorruption`.
- `decorate.test.ts` - the `price()` helper drops `topCorruption`; add a test
  that `decorate` injects **both** the price block and the potion block, that
  the potion block contains the four expected rules, and that decorating an
  already-decorated file twice is idempotent (exactly one of each block).
- Full `npm test` + `npm run typecheck` green; live HC run confirms both blocks
  land in the output filter and potions show their symbols in-game.
